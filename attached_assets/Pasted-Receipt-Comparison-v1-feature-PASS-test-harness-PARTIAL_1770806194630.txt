# Required fix: make Compare entry-point testable without disabling virtualization

## Option A (preferred): add test IDs + deterministic scroll helper

### 1) Add these attributes in `receipts.tsx` (no UI changes)

* On the virtual list scroll container:

  * `data-testid="receipts-virtual-scroll"`
* On each row wrapper:

  * `data-testid={"receipt-row-" + receipt.id}`
* On the actions trigger button:

  * `data-testid={"receipt-actions-" + receipt.id}`
* On the “Compare…” dropdown item:

  * `data-testid={"receipt-compare-" + receipt.id}`

### 2) Update E2E to scroll to a known row before clicking

In Playwright:

* fetch a receipt id from API (you already do this pattern in other tests)
* `page.evaluate` to scroll the container until row testid exists
* then click actions → click compare

This makes the test deterministic and keeps virtualization.

# Concrete E2E algorithm (works)

1. `GET /api/receipts/paged?page=1&pageSize=50` using dev key header (your apiFetch already supports)
2. pick `items[0].receipt_id` as `leftId`
3. Navigate to `/receipts`
4. Wait for table header visible
5. Scroll virtual container to top (ensures first rows render)
6. Click `[data-testid="receipt-actions-${leftId}"]`
7. Click `[data-testid="receipt-compare-${leftId}"]`
8. Assert URL contains `/compare?left=${leftId}`
9. Fill rightId in compare page, load, assert both IDs present

Because you’re using the first item on page 1, it should render near the top—scrolling is minimal.
