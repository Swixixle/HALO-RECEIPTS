# C) Deterministic detectors — exact rules

## C1) transcript_stats

Use only `messages[].role` and `messages[].content`.

* `message_count = messages.length`
* `roles` counts:

  * normalize role to lowercase for counting
  * user/assistant/system/tool buckets, else `other`
* `chars_total`: sum of content length in UTF-16 JS `string.length` (deterministic)
* `chars_by_role`: same bucket scheme
* `avg_chars_per_message = floor(chars_total / message_count)` (0 if empty)
* `max_message_chars` and `max_message_role`: compute max length and role bucket

## C2) timestamp_checks

If any message has `timestamp` field, treat timestamps as “present=true”.

Rules:

* `missing_count`: # messages without timestamp
* `non_iso_count`: timestamps that fail `Date.parse()` OR do not match basic ISO regex `/^\d{4}-\d{2}-\d{2}T/`
* `non_monotonic_count`: count instances where parsed timestamp decreases vs previous (only compare valid parseable timestamps in sequence)
* `notes`: include short notes like “timestamps missing on 3/10 messages”

## C3) content_signals

Compute across all content strings:

* `code_fence_count`: count occurrences of ``` (triple backticks)
* `url_count`: count matches of `/https?:\/\/\S+/g`
* `newline_count_total`: sum of `\n` count
* `non_printable_char_count`: count chars in ranges `[\u0000-\u0008\u000B\u000C\u000E-\u001F]`
* `high_entropy_block_count`:

  * define “block” as any contiguous substring matching base64-ish: `/[A-Za-z0-9+/]{80,}={0,2}/g`
  * count matches

## C4) risk_markers (HEURISTIC ONLY)

All of these are **keyword/phrase detectors**.
Return `present` if count>0.

* `instructional_language` keywords (case-insensitive):
  `\b(do|follow|steps|step|click|run|execute|install|configure|must|should|need to)\b`

* `medical_advice_language`:
  `\b(dose|dosage|mg|mcg|prescribe|diagnos|symptom|treatment|contraindicat|ventilator|oxygen|ABG)\b`

* `legal_advice_language`:
  `\b(lawsuit|liable|attorney|legal advice|statute|contract|jurisdiction)\b`

* `financial_transaction_language`:
  `\b(wire|transfer|bank|routing|account number|ACH|payment|invoice|crypto|send money)\b`

* `self_harm_language`:
  keep minimal and cautious: `\b(suicide|kill myself|self harm)\b`

**Important:** If self-harm marker triggers, add anomaly severity HIGH with message:
“Self-harm language pattern matched (heuristic). Not a diagnosis.”

## C5) pii_heuristics (counts only; mask if examples needed)

Compute counts:

* `email_like_count`: `/[A-Z0-9._%+-]+@[A-Z0-9.-]+\.[A-Z]{2,}/ig`
* `phone_like_count`: `/\b(\+?1[-.\s]?)?\(?\d{3}\)?[-.\s]?\d{3}[-.\s]?\d{4}\b/g`
* `ssn_like_count`: `/\b\d{3}-\d{2}-\d{4}\b/g`
* `dob_like_count`: `/\b(19|20)\d{2}[-\/](0[1-9]|1[0-2])[-\/](0[1-9]|[12]\d|3[01])\b/g`
* `mrn_like_count` (weak heuristic): `/\bMRN[:\s]?\d{6,10}\b/ig`
* `ip_like_count`: `/\b\d{1,3}(\.\d{1,3}){3}\b/g`

**Never claim “PHI.”** Always label as “Potential identifier patterns (heuristic).”

## C6) anomalies list

Add anomalies when:

* empty content string (severity LOW)
* unknown role bucket (LOW)
* non-ISO timestamps present (MEDIUM)
* non-monotonic timestamps (MEDIUM)
* high entropy blocks > 0 (MEDIUM)
* self-harm marker present (HIGH)
