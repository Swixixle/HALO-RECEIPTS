## P7 — Threat Model & Abuse Resistance

### P7.0 Scope Lock

**Goal:** Make the system resilient to adversarial use *without* adding any new epistemic authority.

**Non-goals (keep explicit):**

* No truth scoring
* No reconciliation
* No behavioral inference
* No transcript persistence

## P7.1 Abuse Taxonomy + Controls Matrix (Required Artifact)

Create a single table: **Threat → Attack Path → Impact → Controls → Evidence/Tests**.

### Must-cover threats (minimum set)

1. **Receipt spoofing / replay**

   * Same payload re-submitted to create “false provenance”
2. **Chain manipulation**

   * Attempted “LINKED” chain that should be BROKEN
3. **Key misuse**

   * Expired/revoked key still accepted somewhere
4. **Proof pack confusion attacks**

   * User tries to pass proof pack as “truth certificate”
5. **PII injection**

   * Transcript includes PII to test your “no storage” boundary
6. **Prompt injection into LLM sensor**

   * Transcript tries to coerce forbidden outputs, ranking, “most accurate,” etc.
7. **Resource exhaustion**

   * Large payloads, high concurrency, slowloris-style reads
8. **Rate limit evasion**

   * Multi-IP, header spoofing, distributed low-rate abuse
9. **Error oracle leakage**

   * Using errors to infer internal state (key presence, DB schema, etc.)
10. **Endpoint enumeration**

* Scanning for non-public endpoints, misconfigured auth

11. **Data correlation risk**

* Linking receipt IDs to research IDs, or observation IDs to identity

**Acceptance target:** Every one of these has an explicit mitigation and at least one test.

## P7.2 Input Hardening (Receipt + Transcript Intake)

**Objective:** Make intake safe under adversarial payloads while preserving determinism.

### Required controls

* **Canonical request size enforcement** (you started this in P6.6; expand coverage)
* **Content-type strictness** (reject unexpected types)
* **UTF-8 normalization policy** (avoid homoglyph and canonicalization drift)
* **Structured “safe parse”** for JSON bodies (no prototype pollution style issues)
* **Deterministic truncation rules** *if any truncation exists* (ideally none; prefer rejection)

### Tests

* oversize payload → `PAYLOAD_TOO_LARGE` with canonical envelope
* invalid encoding → `INVALID_REQUEST_BODY`
* JSON weirdness → stable failure (no crash)

---

## P7.3 Proof Pack Misuse Guardrails

**Objective:** Prevent “proof implies truth” misuse.

### Required additions

* Add a **machine-readable disclaimer field** inside the proof pack schema (not prose-only):

  * `proof_scope: ["integrity","signature","chain"]`
  * `proof_scope_excludes: ["truth","completeness","authorship_intent"]`
* Ensure public docs/UI copy never uses “verified” in a way that implies truth (it can mean *cryptographically verified* only).

### Tests

* proof pack always includes the scope fields
* forbidden phrasing not present in API response

## P7.5 Observability Without Leakage

### Required

  * DB state

* Add **security audit events** (forensic_state) for:

  * repeated 401/403
  * rate limit exceeded
  * payload too large
  * forbidden-words rejection
  * kill switch engagement

### Tests

* errors remain canonical and non-revealing
* events logged with stable codes (no secrets)
