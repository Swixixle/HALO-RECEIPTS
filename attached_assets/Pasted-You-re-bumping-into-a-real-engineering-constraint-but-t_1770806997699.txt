You’re bumping into a real engineering constraint, but the conclusion “fully tested” still doesn’t hold **until the Compare entry-point is automation-testable**. The compare page can be fully tested via direct navigation, yes—but the spec explicitly included the row dropdown entry point, and your architect is right to push on it.

The good news: you already have all the right `data-testid`s. The remaining fix is **not** to abandon the entry point—it’s to make the dropdown content test-addressable **and** make Playwright able to click it reliably.

Below are **two acceptable fixes**. Pick A unless you have a strong reason not to.

---

## Fix A (best): make virtualization compatible with table semantics + Playwright clicks

### Why your current setup fails

Absolute-positioned `<tr>` inside a `<table>/<tbody>` is undefined-ish across renderers. Chromium may show it; Playwright screenshots can fail because hit-testing and layout differ. When Playwright can’t compute a stable clickable box, Radix’s trigger won’t open properly (and portal content won’t appear for selectors).

### Minimal structural change (no UX change)

Keep your table header as-is, but render the virtualized “rows” using **CSS grid div rows**, not `<tr>` elements. This makes absolute positioning + transforms predictable.

**Pattern:**

* Header stays `<table>` (or a grid header)
* Body becomes a `div` with role semantics

**Implementation steps (receipts.tsx):**

1. Keep header as your existing table header row.
2. Replace body `<table><tbody>...virtual rows...</tbody></table>` with:

* Scroll container: `div[data-testid="virtual-scroll-container"]`
* Inside: `div` with `height: rowVirtualizer.getTotalSize()` and `position: relative`
* Each virtual row: `div` with:

  * `position: absolute`
  * `transform: translateY(...)`
  * `display: grid`
  * `gridTemplateColumns` matching your 8 columns
  * contains 8 cell `div`s
  * keep your existing testids:

    * `row-receipt-${id}`
    * `button-actions-${id}`
    * `action-compare-${id}`

This preserves virtualization and makes Playwright hit-testing reliable.

### Outcome

* Rows become truly clickable in E2E.
* Radix trigger opens normally.
* Portal menu becomes findable.

---

## Fix B (fallback): keep table, add a deterministic non-menu entry point only in tests

If you refuse to touch structure, the next cleanest approach is: add a hidden-but-accessible Compare trigger that **does not use Radix portals**.

Add an `<a>` link in the actions cell:

* Visible only on hover (so UX impact minimal), **or**
* Present but visually minimal (icon), **or**
* Gate behind `MODE === "e2e"` (I don’t love it, but acceptable if documented)

Example behavior:

* `data-testid="link-compare-${id}"`
* href `/compare?left=${id}`

Then E2E clicks the link instead of using dropdown.

This is acceptable only if you document it as a test affordance.
