# The one thing you must decide for the demo: “VERIFIED” vs “PARTIALLY_VERIFIED”

Your Lantern proof-gate likely expects **VERIFIED**. A demo seed that’s unsigned will only be **PARTIALLY_VERIFIED**, and then Lantern blocks (correctly).

So you have two sane demo options:

## Option 1 (recommended): demo seeds a **fully VERIFIED** receipt

Do **not** commit a private key to the repo.

* Put a demo signing private key into **Replit Secrets**
* Keep only the **public key** (or issuer id) in the repo/trusted registry

### Generate a demo Ed25519 keypair locally (one-time)

Run locally (Mac/Linux):

```bash
node -e "
const { generateKeyPairSync } = require('crypto');
const { publicKey, privateKey } = generateKeyPairSync('ed25519');
console.log('PUBLIC_PEM='); console.log(publicKey.export({ type:'spki', format:'pem' }).toString());
console.log('PRIVATE_PEM='); console.log(privateKey.export({ type:'pkcs8', format:'pem' }).toString());
"
```

Then:

* In Replit → **Secrets**:

  * `DEMO_SIGNER_PRIVATE_PEM` = (private pem)
* In your repo config / key registry:

  * add `DEMO_SIGNER_PUBLIC_PEM` (public pem) as a trusted issuer/signer

Now your demo seed endpoint can:

* build canonical payload → hash
* sign with `DEMO_SIGNER_PRIVATE_PEM`
* verify with public key → result becomes **VERIFIED**

## Option 2 (acceptable): allow Lantern to accept PARTIALLY_VERIFIED **in demo mode only**

This is less pure, but fast:

* Add `DEMO_MODE=true`
* If `DEMO_MODE`, Lantern accepts `PARTIALLY_VERIFIED` but shows an **orange “DEMO: unsigned receipt”** banner.
