### Task 1 — Copy Receipt ID (table + detail)

**Goal:** every receipt ID is copyable with one click, with a deterministic toast.

#### Receipts table (`/receipts`)

* Add a copy icon/button next to the displayed `receipt.id`
* Clicking it copies the exact `receipt.id` string to clipboard
* Show toast: `"Copied receipt ID"` (exact string), success variant

#### Receipt detail (`/receipts/:receiptId`)

* Add the same copy icon/button in the header area next to the ID
* Same toast string

**Implementation requirements**

* Use `navigator.clipboard.writeText(receipt.id)`
* If clipboard fails, show toast: `"Copy failed"` (exact string)

**Tests**

* Don’t mock clipboard globally in a brittle way; provide a minimal clipboard stub in the test setup.

### Task 3 — Risk Summary strip on detail page

**Goal:** operator sees risk posture before reading anything.

Add a compact strip near the top of detail page:

* Title: **“Risk Summary”**
* Chips:

  * **PII** (with total count)
  * **RISK** (count of risk markers)
  * **ANOM** (count of anomalies)
* If no forensics data: show `—` (em dash) in place of chips.

**Counts logic (same as table)**

* PII count = sum of any available numeric keys under `pii_heuristics` (e.g., email/phone/ssn). If keys unknown, count any numeric > 0.
* RISK count = `risk_markers.length` (or 0)
* ANOM count = `anomalies.length` (or 0)

**Rules**

* Must not re-parse JSON repeatedly. Use the existing memoized/cached forensics parse helper.
* Risk Summary must render safely even if `forensicsJson` is missing or malformed.

**Tests**

* For a receipt with forensics: chips show correct labels and counts
* For missing forensics: displays `—`

### Task 4 — Export guardrail wording + friction (confirm-and-allow stays)

**Goal:** export remains allowed under kill switch (policy), but operator must explicitly acknowledge risk.

If export is triggered and either condition is true:

* PII present **OR**
* kill switch engaged

Then show a confirmation dialog.

**Dialog copy (exact strings)**

* Title: `"Confirm Export"`
* Body (include both warnings when applicable):

  * If PII: `"This receipt contains detected PII. Exporting may increase exposure risk."`
  * If kill switch: `"Kill switch is engaged. Interpretation is blocked, but forensic export is permitted for evidence preservation."`
* Buttons:

  * Cancel: `"Cancel"`
  * Confirm: `"Export anyway"`

**Rules**

* Export should not proceed unless confirm clicked.
* If neither PII nor kill switch: export proceeds immediately (no dialog).

**Tests**

* Update the existing export test:

  * When PII present → click export → confirm dialog appears → click “Export anyway” → endpoint called
  * When no PII and no kill switch → export calls endpoint without dialog
