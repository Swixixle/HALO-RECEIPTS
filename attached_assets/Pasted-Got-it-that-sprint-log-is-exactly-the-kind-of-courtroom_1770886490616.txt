## 3) CI: split “deterministic build” vs “time-bound proof bundle”

You’ve added a lot of tests (72) and new runtime evidence modes. Make CI outcomes crisp:

### Recommended CI structure

* **Job A — Determinism gate**: rebuild verifier zip, compare SHA-256
* **Job B — Test gate**: run all tests
* **Job C — Proof bundle**:

  * only runs in an environment where anchors are available
  * runs `--anchors=required`
  * uploads proof artifacts

### Why this matters

It prevents people from confusing “verifier reproducibility” with “proof bundle reproducibility” (which can never be fully deterministic because TSA is time-based).
