## 4) Row expansion (NO transcript leak)

Each row must have an expand control (chevron or “…” menu) that reveals exactly **three actions**:

1. **Show verification report**
2. **Open receipt viewer**
3. **Export forensic JSON**

No other actions. No edit/delete. No transcript preview.

### Action behavior

#### 4.1 Show verification report

* Opens a read-only modal or drawer that displays ONLY:

  * Hash card (match/mismatch + algo + canonicalization)
  * Signature card (status + key id + issuer)
  * Chain card (status + previous link)
* This report must be sourced from:

  * existing verify report endpoint, OR
  * proof pack endpoint `GET /api/public/receipts/:id/proof` (preferred for read-only)

#### 4.2 Open receipt viewer

* Navigates to Receipt Viewer route for that receipt (whatever your existing route is)
* Pass receipt_id only; do not pass transcript content in state

#### 4.3 Export forensic JSON

* Triggers download using the existing forensic export endpoint.
* If endpoint is private, require x-api-key proxy pattern; do not call it directly from browser if that violates your CLIENT_INTEGRATION.md rules.
* If you can’t call it safely from browser, render the action disabled with tooltip:

  * `Requires server proxy (x-api-key)`
    (this text is allowed)
