## Sprint A — Make the release mechanically undeniable

### A1) Release reproducibility gate

**Goal:** anyone can rebuild the verifier zip from a tag and byte-compare (or at least hash-compare) to the published artifact.

**Do**

* Add a CI job that:

  * checks out the tag
  * builds `verifier-vX.Y.Z.zip`
  * computes SHA-256
  * compares against the checksum file you publish in the release

**Acceptance**

* CI fails if the rebuilt zip hash ≠ release zip hash.

**If this fails today**

* You likely have nondeterminism from:

  * zip timestamps / ordering
  * embedding build time
  * `git describe` vs exact tag
  * node module resolution differences

Fix: zip with normalized timestamps + stable file ordering (or use `bsdtar`/`zip -X` style flags).

---

### A2) Artifact signing (not just checksums)

Checksums are good; signatures make it “court-friendly.”

**Do (minimal, strong)**

* Sign release artifacts (verifier zip + proof bundle zip + checksums) with **Sigstore Cosign** (keyless OIDC is fine for now).

**Acceptance**

* Release includes `.sig` and/or transparency log verification instructions in `PROOF_BUNDLE.md`.

## Sprint C — External anchoring MVP: choose a trust domain

You don’t need to pick the perfect anchor. You need to pick a **separate trust boundary** that breaks the “DB superuser rewrites everything” scenario.

### C0) Pick one anchoring target (recommended order)

1. **S3 Object Lock (WORM)**

   * Strong separation if AWS account policies are tight
   * Practical, not philosophical

2. **RFC3161 TSA timestamp receipts**

   * Great “external time oracle”
   * Lightweight, strong legal intuitions

3. **Transparency log / append-only public log**

   * Strong, but may introduce “public exposure” concerns

### C1) Define the anchor payload (keep it small)

Anchor exactly:

* `checkpoint_id`
* `checkpoint_seq`
* `event_seq`
* `event_hash`
* `checkpoint_hash` (or signed payload hash)
* `engine_id`
* `audit_payload_version`
* `kid`
* `timestamp`

**Acceptance**

* The anchor payload is constant-size and does not include PHI.

### C2) Implement one real anchor backend

You already have an interface + stub. Ship one.

**Acceptance**

* Proof run can optionally:

  * create checkpoints
  * anchor them externally
  * export pack that includes anchor receipts
  * offline verifier can validate anchor receipts (or at least validate their signature/hash chain)
