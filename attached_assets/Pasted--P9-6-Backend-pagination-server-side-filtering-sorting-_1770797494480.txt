# Replit Agent Instructions — P9-6 (NO DEVIATIONS)

### Objective

Upgrade `GET /api/receipts` from “return all receipts” to **paged, filtered, sorted** results while preserving backwards compatibility via a new endpoint or optional mode.

You will implement:

1. `GET /api/receipts` supports query params:

* `page` (1-based, default `1`)
* `pageSize` (default `50`, max `200`)
* `status` (optional: `VERIFIED|PARTIALLY_VERIFIED|UNVERIFIED`)
* `q` (optional search; receipt id substring match)
* `hasForensics` (optional: `true|false`)
* `killSwitch` (optional: `true|false`)
* `sort` (optional: `createdAt`)
* `order` (optional: `asc|desc`, default `desc`)

2. Response shape:

```json
{
  "items": [/* receipts */],
  "total": 46,
  "page": 1,
  "pageSize": 50,
  "totalPages": 1
}
```

3. Add DB indexes to support these queries.

4. Update frontend `/receipts` to use server pagination (infinite or numbered). Keep virtualization.

5. Update tests + E2E accordingly.

No other endpoints are changed.

## Step 1 — Add a new paged endpoint OR mode (compat rule)

### Rule

Do NOT silently break existing clients.

Pick ONE:

**Option A (preferred):** Add a new endpoint:

* `GET /api/receipts/paged`

Leave existing `GET /api/receipts` returning full list.

**Option B:** Keep same endpoint but add a flag:

* `GET /api/receipts?mode=paged`

If `mode` absent → old behavior.

✅ Use Option A unless the codebase already expects the same route.

---

## Step 2 — Implement query parsing + validation

* Parse ints safely; clamp bounds.
* `page >= 1`
* `pageSize in [1..200]`
* If invalid param: return `400` with JSON `{ "error": "Invalid <param>" }`

Allowed status values only.

Boolean params accept: `true|false` (case-insensitive). Anything else → 400.

---

## Step 3 — Implement SQL WHERE / ORDER / LIMIT/OFFSET

### Filters

* `status` maps to `verification_status = ?`
* `q` does `receipt_id LIKE '%' || ? || '%'` (or equivalent)
* `hasForensics=true` means `forensicsJson IS NOT NULL AND forensicsJson != ''`
* `hasForensics=false` means `forensicsJson IS NULL OR forensicsJson == ''`
* `killSwitch=true` means `hindsightKillSwitch = 1`
* `killSwitch=false` means `hindsightKillSwitch = 0`

### Sorting

* Only support `createdAt` for now.
* Default: `ORDER BY createdAt DESC`
* Tie-breaker: `ORDER BY createdAt DESC, receipt_id DESC` (stable)

### Pagination

* `offset = (page - 1) * pageSize`
* Query 1: `SELECT ... FROM receipts WHERE ... ORDER BY ... LIMIT ? OFFSET ?`
* Query 2: `SELECT COUNT(*) FROM receipts WHERE ...`

Return `totalPages = ceil(total/pageSize)`.

---

## Step 4 — Add indexes (SQLite)

Add indexes that match query patterns:

* `CREATE INDEX IF NOT EXISTS idx_receipts_createdAt ON receipts(createdAt);`
* `CREATE INDEX IF NOT EXISTS idx_receipts_verification_status ON receipts(verification_status);`
* `CREATE INDEX IF NOT EXISTS idx_receipts_killswitch ON receipts(hindsightKillSwitch);`

For forensics presence, indexing `forensicsJson` isn’t great; leave it.

If you do substring search on `receipt_id`, a normal index may not help (LIKE %x%). Still add:

* `CREATE INDEX IF NOT EXISTS idx_receipts_receipt_id ON receipts(receipt_id);`

**Implementation rule:** migrations must run automatically on server start if that’s your pattern. Do not add a manual migration step.
