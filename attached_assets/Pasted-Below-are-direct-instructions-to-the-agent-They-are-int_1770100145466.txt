Below are direct instructions to the agent.
They are intentionally restrictive. This is how you add LLMs without creating an AI judge.

⸻

🧭 LLM INTEGRATION DIRECTIVE (P6 – SENSOR MODE ONLY)

Core Rule (Non-Negotiable)

LLMs are sensors, not arbiters.
They may observe, summarize, or flag, but they may never decide truth, validity, intent, or correctness.

If an LLM output could be mistaken for a verdict, it is out of scope.

⸻

1) Allowed Role of LLMs

LLMs may be used only for:

✅ Pattern Observation
	•	Surface possible ambiguities
	•	Identify areas of disagreement
	•	Highlight uncertainty or multiple interpretations
	•	Rephrase content without adding conclusions

✅ Comparative Description
	•	“Model A emphasized X, Model B emphasized Y”
	•	“Responses differ in tone/structure/focus”

✅ Language-Level Signals (Non-Authoritative)
	•	Hedging language
	•	Confidence markers
	•	Safety disclaimers
	•	Refusals vs compliance styles

LLMs are descriptive instruments, not evaluators.

⸻

2) Explicitly Forbidden Uses

LLMs must never:

❌ Decide whether something is true / false
❌ Declare hallucinations
❌ Score accuracy, safety, or correctness
❌ Override cryptographic or forensic results
❌ Produce a single “final interpretation”
❌ Rank models as “better” or “worse”
❌ Recommend actions or judgments

If a sentence starts with:
	•	“This means…”
	•	“Therefore…”
	•	“The correct answer is…”
	•	“This is misleading because…”

→ Delete it.

⸻

3) Data Flow Isolation (Critical)

LLMs:
	•	Do NOT see:
	•	Hash results
	•	Signature status
	•	Chain status
	•	Verification outcome
	•	Do NOT write to:
	•	verification_status
	•	research dataset
	•	forensic facts

LLMs:
	•	Operate on:
	•	Transcript (subject to TRANSCRIPT_MODE)
	•	Explicitly labeled input scope
	•	Write to:
	•	llm_observations[] (new, separate structure)

⸻

4) Output Schema (Mandatory)

All LLM outputs MUST conform to this shape:

{
  "schema": "llm-observation/1.0",
  "model_id": "gpt-4o | claude-3 | etc",
  "observation_type": "paraphrase | ambiguity | disagreement | tone",
  "based_on": "submitted_transcript | verified_transcript",
  "content": "neutral descriptive text",
  "confidence_statement": "This is a model-generated observation, not a factual determination.",
  "limitations": [
    "Model may miss context",
    "Model does not assess truth or accuracy"
  ]
}

No free-form prose.
No missing disclaimers.

⸻

5) UI Rules

In the UI:
	•	LLM output must be visually separated from:
	•	Facts
	•	Verification
	•	Forensics
	•	Label clearly:
“Model Observation (Non-Authoritative)”
	•	Never show LLM output by default in public views
	•	Hide entirely if kill_switch_engaged = true

⸻

6) Research Dataset Boundary

LLM outputs:
	•	❌ Do NOT enter the Research Dataset
	•	❌ Do NOT affect research exports
	•	❌ Do NOT affect metrics or counts

If LLMs are later studied, they get:
	•	A separate dataset
	•	A separate consent scope
	•	A separate schema

No contamination.

⸻

7) Test Requirements

Before claiming completion, provide:
	1.	A test showing:
	•	LLM output exists
	•	verification_status unchanged
	2.	A test showing:
	•	Two LLMs disagree
	•	System displays disagreement without reconciliation
	3.	A grep proving:
	•	LLM output never contains “correct”, “true”, “false”, “hallucination”

⸻

8) Language Hygiene Rule (Very Important)

LLMs must use:
	•	“may”
	•	“appears”
	•	“could be interpreted as”

LLMs must NOT use:
	•	“is”
	•	“means”
	•	“therefore”
	•	“this proves”

If the agent is unsure whether language crosses the line:
👉 Remove it.

⸻

Stop Condition

After implementing:
	•	Pause
	•	Produce an evidence packet
	•	Wait for architect approval

No iteration loops. No feature creep.

⸻

Final reminder to agent

This system measures reality.
LLMs only describe how text might be perceived.
The moment an LLM sounds confident, you’ve broken the system.

Proceed carefully.
