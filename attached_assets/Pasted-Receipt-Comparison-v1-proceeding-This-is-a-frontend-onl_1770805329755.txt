# Receipt Comparison v1 — STRICT SPEC (NO BACKEND CHANGES)

## Goal

Enable operators to compare **two receipts side-by-side** with:

* top-level status deltas (verification/signature/chain/kill switch)
* forensics deltas (PII, risk markers, anomalies)
* key metadata deltas (createdAt, signer/key id if present)
* quick actions: View Detail, Open Proof Pack, Export (existing flow)

No new APIs. Use existing:

* `GET /api/receipts/:receiptId` (or whatever your detail page already uses)
* `GET /api/public/receipts/:id/proof`
* `GET /api/receipts/:id/export` (existing export endpoint)
* Auth banner behavior consistent with other private pages.

# Routing

## New page route

Create a new page:

`/compare`

Query params:

* `left=<receiptId>`
* `right=<receiptId>`

Rules:

* If either is missing → show empty state with two input fields.
* If both present → load both receipts and render compare view.
* Any change to left/right should update URL (shallow navigation is fine).

---

# UI requirements

## Layout

* Header: “Receipt Comparison”
* Two selection panels (Left / Right):

  * Receipt ID input (or combobox if you already have one; v1 uses input)
  * “Load” button (optional; can auto-load on debounce)
  * “Swap” button swaps left/right IDs
* Main compare content: two-column grid.

## Compare summary strip (top)

Show for each side:

* verification status
* signature status
* chain status
* kill switch state
* forensics presence

Between them, show delta indicators:

* “DIFF” badge if different, “MATCH” if same.

## Forensics compare (must exist)

Use existing parse logic (same as receipts/detail):

* PII counts (email/phone/ssn)
* risk markers count
* anomalies count

Render as:

* Left chips vs Right chips
* If forensics missing: show em dash

## Key fields compare (v1 set)

Compare these fields explicitly (table rows):

* receipt_id
* createdAt
* verification_status
* signature_status
* chain_status
* hindsightKillSwitch
* hasForensics
* (optional if present) signer id / key id / model id

For each row:

* left value
* right value
* diff indicator (only if different)

## Actions (per side)

Each side gets buttons:

* “View Detail” → `/receipts/:id`
* “Open Proof Pack” → `/api/public/receipts/:id/proof` in new tab
* “Export” → reuse existing export flow:

  * If you already have the export confirmation modal logic, reuse it.
  * Must honor kill switch / PII warning semantics already defined.

## Auth handling

If a private fetch fails 401/403:

* show the existing AuthRequiredBanner (same as receipts/detail/sensors)
* do not show “not found” in that case.
